# 内容工作台：第一阶段 PRD 与交互契约

## 目标与边界

个人可信使用，沿用 Access、单 GPU 串行 worker、SQLite。用户管理内容，而非重复运行的流水账。本阶段交付内容库、执行历史、重复识别、明确反馈、阅读、基础导出、归档与回收站。原链接、任务 API、原结果全部保留。不上公开注册、计费或多用户；不修改 Tunnel。

## 核心模型

内容拥有稳定 ID；一次处理是一个 job。旧 retry_of 链归入同一内容，旧独立任务不擅自合并。URL 规范化识别常见平台视频 ID，并结合输出语言和处理选项检测重复；上传按文件 SHA-256 与语言识别。同一内容同时最多一个活动执行。重试创建新的执行但不新建内容；结果按每次执行保留，阅读可选择旧版本。

## 交互契约

- 提交/重试立即显示提交中；同次操作复用请求键，超时不冒充失败，允许使用原键确认/重发。
- 输入自动保留在当前浏览器会话；上传仅保留文件名提示，不能假装刷新后仍持有文件。
- 重复提交默认打开已有内容（回收站内容也不偷偷恢复）；用户可在详情明确选择重试/重新处理。
- 列表只展示一份内容；最新状态与执行次数明确。旧 task 链接解析到所属内容并保留所选执行。
- 网页断开、worker 离线、任务失败是三种不同状态；断线保留已显示内容。
- 排队可取消；运行中取消本阶段不提供，避免仅改状态却仍占 GPU。
- 运行/排队内容不可归档或丢弃；回收站为软删除，可恢复，无自动永久删除。
- 重试不覆盖旧成果；部分结果即时可读；未实现分阶段恢复时明确告知将重新处理整条流水线。
- 完成后正文优先。轮询只在内容数据变化时重绘，不因心跳破坏滚动/选择。
- 复制/MD/TXT 导出沿用认证。AI 整理与识别原文明确标记，不承诺绝对准确。

## 验收

旧库幂等迁移；旧链接可读；重复与并发提交；双击与响应丢失重试；重试同内容多执行；回收站恢复；取消与 worker 领取竞态；部分结果/旧版本导出；搜索筛选；SSE 断开恢复；桌面与手机；公网 Access 页面/API/下载；不改 Tunnel。
